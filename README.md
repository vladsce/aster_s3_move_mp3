# s3-archiver

Фоновый сервис смотрит каталог с записями, находит файлы старше заданного срока и переносит их в S3-совместимое хранилище. После проверки, что объект в бакете совпал с локальным файлом, сервис удаляет файл с диска. Старая запись остаётся только в S3.

Внутри контейнера каталог записей всегда `/data/records`. Путь на хосте задаётся переменной `HOST_RECORDS_DIR`.

## 1. Требования

Нужны Docker и Docker Compose. Сервис собирается и запускается из контейнера.

## 2. Настройка

Скопируйте `.env.example` в `.env` и заполните значения в редакторе.

Реквизиты S3 берутся в панели хостера: **Облачные решения → Объектное хранилище (S3) → Управление → Доступы**. Оттуда же берётся имя бакета. Адрес по умолчанию: `https://s3.hoster.by`.

Файл `.env` в образ не копируется. Compose подставляет его в окружение контейнера в момент запуска. Ключи доступа в журнал не пишутся.

| Переменная | Назначение |
| --- | --- |
| `HOST_RECORDS_DIR` | Существующий каталог записей на хосте |
| `HOST_LOGS_DIR` | Каталог журналов на хосте, по умолчанию `./logs` |
| `PUID`, `PGID` | UID и GID пользователя внутри контейнера, по умолчанию `1000:1000` |
| `TZ` | Часовой пояс, по умолчанию `Europe/Chisinau` |
| `AGE_MONTHS` | Возраст файла в месяцах, по умолчанию `3` |
| `CHECK_INTERVAL_SECONDS` | Пауза между проходами, по умолчанию `300` |
| `FILE_EXTENSIONS` | Расширения через запятую, по умолчанию `.mp3` |
| `S3_ENDPOINT` | Адрес хранилища |
| `S3_ACCESS_KEY`, `S3_SECRET_KEY`, `S3_BUCKET` | Доступ и бакет |
| `S3_REGION` | Регион подписи, по умолчанию `us-east-1` |
| `S3_ADDRESSING_STYLE` | `path` или `virtual`, по умолчанию `path` |
| `S3_PREFIX` | Необязательный префикс ключей, например `records/` |
| `DELETE_AFTER_UPLOAD` | Удалять локальный файл после успешной проверки, по умолчанию `true` |
| `DRY_RUN` | Только записать в журнал предполагаемые действия, по умолчанию `false` |
| `LOG_LEVEL` | Уровень журнала, по умолчанию `INFO` |

Ключ объекта собирается как `S3_PREFIX` плюс путь файла относительно `/data/records`. Вложенные папки сохраняются. Символические ссылки сервис пропускает.

Возраст считается через `relativedelta` от текущего времени и сравнивается с временем изменения файла.

## 3. Права

Контейнер работает от пользователя `PUID:PGID` и должен иметь право изменять каталог записей: после подтверждённой загрузки он удаляет локальный файл. Для удаления нужна запись в сам каталог, поэтому том подключён в режиме read-write.

`PUID` и `PGID` — это UID и GID владельца записей. Узнать их можно так, когда `.env` уже указывает на каталог и образ собран:

```bash
docker compose run --rm --build --user 0:0 --entrypoint python archiver -c "import os; from pathlib import Path; root=Path('/data/records'); st=root.stat(); print('dir', st.st_uid, st.st_gid); files=[p for p in root.rglob('*') if p.is_file() and not p.is_symlink()]; print('files', len(files)); [print(p.stat().st_uid, p.stat().st_gid, p) for p in files[:10]]"
```

Первое число — UID, второе — GID. Впишите их в `PUID` и `PGID`. Compose применяет пользователя при запуске.

Каталог логов тоже должен быть доступен этому пользователю. Если он создался от root, передайте его владельцу из `.env`:

```bash
docker compose run --rm --user 0:0 --entrypoint python archiver -c "import os; path='/var/log/archiver'; os.makedirs(path, exist_ok=True); os.chown(path, int(os.environ['PUID']), int(os.environ['PGID'])); os.chmod(path, 0o775); print('ok', os.environ['PUID'], os.environ['PGID'])"
```

Эта команда с `--user 0:0` только выставляет владельца каталога логов. Постоянный сервис работает от `PUID:PGID`.

Журнал пишется в `/var/log/archiver/archiver.log` и одновременно в stdout. Файл ротируется: 10 МБ, 5 архивов.

## 4. Безопасный порядок первого запуска

Сначала посмотрите, что сервис нашёл бы, без загрузки и без удаления:

```bash
docker compose stop archiver
docker compose run --rm --build archiver python -m app.main --once --dry-run
```

В журнале у каждого файла есть путь, ключ S3 и размер. Строка `итог прохода` показывает, сколько файлов найдено и какой объём был бы загружен. Код выхода `1` означает, что проход записал ошибки.

Затем в `.env` поставьте `DELETE_AFTER_UPLOAD=false` и сделайте один боевой проход. Файлы уйдут в бакет и останутся на диске:

```bash
docker compose run --rm archiver python -m app.main --once
```

Откройте бакет в панели хостера и сверьте ключи и размеры с журналом.

Когда объекты на месте, верните `DELETE_AFTER_UPLOAD=true` и запустите постоянную работу:

```bash
docker compose up -d --build
```

Пока сервис запущен, разовый проход получит отказ по lock-файлу: каталог логов общий, и два прохода не идут одновременно. Перед `--once` остановите сервис:

```bash
docker compose stop archiver
```

Останов по `docker stop` дожидается текущего файла и завершает процесс. На это отведено 60 секунд.

Если S3 недоступен, процесс остаётся работать: ошибка пишется в журнал, локальный файл не удаляется, следующая попытка будет на следующем проходе.

## 5. Журнал, состояние, остановка, обновление

Журнал контейнера:

```bash
docker compose logs -f archiver
```

Файл журнала лежит на хосте в каталоге `HOST_LOGS_DIR` (`./logs`, если переменная не задана), имя файла `archiver.log`.

Состояние и healthcheck:

```bash
docker compose ps
```

В конце каждого прохода сервис обновляет `/tmp/heartbeat`. Проверка считает контейнер живым, пока этот файл свежее, чем `3 × CHECK_INTERVAL_SECONDS`. Статус `unhealthy` значит, что проход не завершился в этот срок.

Остановка:

```bash
docker compose down
```

`docker compose down` останавливает и убирает контейнеры. Записи в каталоге на хосте и объекты в бакете остаются. Сервис не удаляет объекты из бакета.

Обновление после изменения кода или `.env`:

```bash
docker compose up -d --build
```

## 6. Запуск тестов

Тесты используют временный каталог внутри контейнера и не подключают боевой каталог записей.

```bash
docker compose --profile test run --rm --build tests
```

Та же команда без пересборки, если образ уже собран:

```bash
docker compose --profile test run --rm tests
```

## 7. Ошибка подписи или адресации

Если хранилище отвечает ошибкой подписи, `AuthorizationHeaderMalformed` или отказом из-за адреса бакета, смените в `.env` значение `S3_ADDRESSING_STYLE` с `path` на `virtual` или обратно. Для hoster.by обычно подходит `path`.

Повторите проверку без изменений:

```bash
docker compose run --rm archiver python -m app.main --once --dry-run
```
